# قرارداد مدیریت پروژه‌ها

## هدف

این مخزن باید در هر زمان بتواند به چهار سؤال پاسخ دهد:

1. چه پروژه‌هایی داریم؟
2. در هر پروژه اکنون روی چه چیزی کار می‌کنیم؟
3. چه چیزی واقعاً انجام شده و نتیجه آن چه بوده است؟
4. مانع و اقدام بعدی چیست؟

## لایه‌های اطلاعات

| لایه | فایل | کاربرد |
|---|---|---|
| سبد پروژه‌ها | `/README.md` | وضعیت و لاگ کلان همه پروژه‌ها |
| پروژه | `projects/<slug>/README.md` | هدف، حوزه‌ها، وضعیت و لاگ پروژه |
| حوزه کاری | `workstreams/<area>/README.md` | هدف، KPI، وضعیت و اقدام بعدی |
| برنامه | `ROADMAP.md` | کارهای آینده با ترتیب و وابستگی |
| گزارش | `reports/` | نتیجه یک بررسی، کمپین یا بازه زمانی |
| داده | `data/` | خط مبنا، خروجی خام یا داده ساختاریافته |
| تصمیم | `decisions/` | تصمیم‌های مهم همراه دلیل و پیامد |

## وضعیت‌های استاندارد

| وضعیت | معنی |
|---|---|
| `idea` | هنوز ارزیابی یا تأیید نشده |
| `planned` | در برنامه است ولی ورودی یا زمان اجرا کامل نیست |
| `ready` | ورودی و معیار پایان کامل و آماده اجرا است |
| `in-progress` | اجرای واقعی آغاز شده است |
| `blocked` | مانع مشخص دارد و مانع باید نوشته شود |
| `done` | معیار پایان برآورده و نتیجه ثبت شده است |
| `monitoring` | اجرا شده و در انتظار داده نتیجه است |
| `cancelled` | با دلیل روشن متوقف شده است |

## قواعد گزارش‌دهی

- READMEها خلاصه و قابل‌خواندن برای مدیر هستند.
- هر ادعای عددی باید تاریخ و منبع داشته باشد.
- «انجام شد» بدون شاهد، URL، فایل، commit یا نتیجه آزمون معتبر نیست.
- کار برنامه‌ریزی‌شده و کار انجام‌شده در دو بخش جدا نگهداری می‌شوند.
- گزارش‌های دوره‌ای جایگزین وضعیت جاری نمی‌شوند؛ وضعیت جاری باید بعد از گزارش نیز به‌روز شود.

## افزودن پروژه جدید

1. `templates/project/README.md` را در `projects/<slug>/README.md` کپی کن.
2. پروژه را به جدول README ریشه اضافه کن.
3. فقط حوزه‌هایی را بساز که واقعاً فعال یا برنامه‌ریزی شده‌اند.
4. برای هر حوزه از `templates/workstream/` استفاده کن.
5. اولین خط مبنا، مالک تصمیم و اقدام بعدی را ثبت کن.
